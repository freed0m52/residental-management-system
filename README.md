# Система управления жилым комплексом

Консольное приложение для управления многоквартирным жилым комплексом.

## Назначение

Приложение автоматизирует управление жилым комплексом: учёт жильцов и помещений, обработку заявок на обслуживание и ведение дополнительных услуг.

## Целевая аудитория

- Управляющая компания (администраторы)
- Жильцы комплекса (собственники и арендаторы)
- Сотрудники обслуживающих служб

## Предметная область

Жилой комплекс включает жилые и нежилые помещения, в которых проживают жильцы. Жильцы подают заявки на обслуживание (ремонт, уборка, сантехника) и могут подключать дополнительные услуги (парковка, клининг).

## Основные классы

### Resident (Житель)
Житель жилого комплекса.

**Атрибуты:** `id`, `full_name`, `apartment_number`, `phone`, `status`

**Методы:**
- `is_owner()` — является ли житель собственником
- `__str__()` — строковое представление
- `from_data()` — создание из словаря (JSON)
- `to_dict()` — преобразование в словарь (JSON)

### Premise (Помещение)
Жилое или коммерческое помещение.

**Атрибуты:** `id`, `number`, `premise_type`, `area`, `is_occupied`

**Методы:**
- `occupy()` / `vacate()` — занять / освободить
- `is_living()` — является ли помещение жилым
- `__str__()`, `from_data()`, `to_dict()`

### Request (Заявка)
Заявка на обслуживание.

**Атрибуты:** `id`, `resident` (объект Resident), `apartment_number`, `request_type`, `description`, `is_urgent`, `status`, `created_at`, `department`

**Методы:**
- `complete()` — отметить выполненной
- `mark_urgent()` — сделать срочной
- `is_completed()` — проверка статуса
- `__str__()`, `from_data()`, `to_dict()`

### Service (Услуга)
Дополнительная услуга.

**Атрибуты:** `id`, `name`, `cost`, `period`, `is_active`

**Методы:**
- `activate()` / `deactivate()` — активировать / деактивировать
- `get_annual_cost()` — годовая стоимость
- `__str__()`, `from_data()`, `to_dict()`

## Взаимодействие объектов

- `Request` хранит **объект** `Resident`, а не только его ID
- `Resident` связан с помещением через `apartment_number`
- Один житель может подать много заявок
- При сохранении в JSON объектные ссылки заменяются на ID, при загрузке — восстанавливаются

## Хранение данных

Данные хранятся в JSON-файлах каталога `data/`. При загрузке JSON преобразуется в объекты классов (`Resident`, `Premise`, `Request`, `Service`), при сохранении — обратно в JSON. Для связанных объектов в JSON хранятся только их идентификаторы.
